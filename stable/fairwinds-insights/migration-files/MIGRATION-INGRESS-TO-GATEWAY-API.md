# Migrating Fairwinds Insights from Ingress to Gateway API

Chart 10.6.0 adds optional `HTTPRoute` and `GRPCRoute` resources. They are independent of Ingress, allowing both routing stacks to run during migration.

The chart creates Routes only. Install the Gateway API CRDs and configure the Gateways separately before enabling them.

## Prerequisites

- Gateway API CRDs that include `gateway.networking.k8s.io/v1` `HTTPRoute` and `GRPCRoute`
- HTTP and gRPC Gateway listeners whose hostnames match the Route hostnames
- Gateway `allowedRoutes` configuration that permits Routes from the Insights namespace
- DNS or a temporary Host-header test path to the Gateway

## Configure Routes

Route hostnames are complete DNS names. They do not inherit `ingress.hostedZones`, `sanitizedBranch`, or gRPC Ingress hosts.

```yaml
httpRoute:
  enabled: true
  parentRefs:
    - name: insights-http
      namespace: kgateway-system
      sectionName: https
  hostnames:
    - insights.example.com

grpcRoute:
  enabled: true
  parentRefs:
    - name: insights-grpc
      namespace: kgateway-system
      sectionName: grpc
  hostnames:
    - grpc.insights.example.com

api:
  grpc:
    enabled: true
```

`parentRefs` and `hostnames` are required when the corresponding Route is enabled.

When translating existing Ingress values:

- Replace the generated `sanitizedBranch` + `ingress.hostedZones` names with complete entries in `httpRoute.hostnames`.
- Copy `api.grpc.ingress.hosts` into `grpcRoute.hostnames`, or write out the hostname previously generated by the chart.
- Replace `openApi.ingress.enabled` with `httpRoute.openApi.enabled`.
- Replace `api.ingress.enabled` with `httpRoute.api.enabled`.
- Replace `admissionApi.ingress.enabled` and its wildcard path with `httpRoute.admissionApi.enabled` and the equivalent regular expression path.
- Replace `mcp.ingress.enabled` with `httpRoute.mcp.enabled`.
- Replace `api.grpc.ingress.enabled` with `grpcRoute.enabled`. Keep `api.grpc.enabled` enabled because it creates the gRPC backend port.

## Configure HTTP paths

HTTP paths are controlled independently from Ingress:

```yaml
httpRoute:
  openApi:
    enabled: true
    path: /swagger
  api:
    enabled: true
    path: /v0
  admissionApi:
    enabled: false
    path: /v0/organizations/[^/]+/clusters/[^/]+/data/admission/submit
  mcp:
    enabled: false
    path: /mcp
```

The admission route also requires `admissionApi.enabled: true`. The MCP route also requires `mcp.enabled: true`. The dashboard catch-all route at `/` is always included.

## Dual-stack rollout

1. Keep `ingress.enabled: true`.
2. Enable and configure `httpRoute` and, when needed, `grpcRoute`.
3. Do not add ExternalDNS annotations until Route status reports `Accepted=True` and `ResolvedRefs=True`.
4. Test the Gateway directly with the production hostname in the Host header.
5. Move DNS to the Gateway.
6. Disable Ingress after the Gateway path is stable.

Ingress annotations are not copied to Routes. Add Gateway-specific annotations under `httpRoute.annotations` or `grpcRoute.annotations`.

## Rollback

Move DNS back to the Ingress endpoint, then disable the Routes. Keeping Ingress enabled during migration makes rollback independent of a chart deployment.
